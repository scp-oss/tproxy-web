# tproxy-web

Прокси для Telegram в одном контейнере: панель управления и три модуля,
которые включаются в ней по отдельности.

| Модуль | Для чего | Как выходит в Telegram |
|---|---|---|
| **WEB** | Telegram Desktop 7.1.1+ (тип прокси WEB) | [tproxy-server](https://github.com/telegramdesktop/tproxy-server) → [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) → свой Cloudflare Worker |
| **MTProto** | любой клиент, fake-TLS | tg-ws-proxy → свой Cloudflare Worker |
| **SOCKS5** | локальная сеть; звонки — **только iPhone**, на Android используйте VPN | выход за границу (Shadowsocks), если задан, иначе Cloudflare Worker |
| **WireGuard для Telegram** (экспериментально) | звонки на Android и iPhone | тот же выход; в туннель идёт только Telegram |

Панель работает всегда, даже когда все модули выключены или упали.
Упавший модуль перезапускается сам, ошибка видна в панели.

## Как устроено

```text
            ┌──────────────────── контейнер tproxy-web ────────────────────┐
 :7655  ──▶ │ tproxyd: панель (логин/пароль)                               │
 :19443 ──▶ │ tproxyd: вход WEB-прокси ─▶ tproxy-server ─▶ tg-ws-proxy ─┐  │
 :8444* ──▶ │          (путь панели ─▶ панель, чужие ─▶ страница входа)  │  │
 :MTProto ▶ │ tg-ws-proxy (fake-TLS) ─────────────────────────────────────┤──▶ Cloudflare Worker ─▶ Telegram
 :SOCKS5 ─▶ │ tproxyd SOCKS5 (TCP+UDP) ─▶ sing-box ─┬─▶ Shadowsocks-выход ─┼──▶ сервер за границей ─▶ Telegram
            │                                       └─▶ Worker (только TCP)┘  │
            └──────────────────────────────────────────────────────────────┘
 * порты входа (HTTP для прокси и прямой HTTPS) — в панели, сертификат из ./certs
```

`tproxyd` (Go) — главный процесс: панель, вход, запуск модулей. Docker-сокет
ему не нужен. Все секреты и настройки лежат в томе `/config`.

## Установка

Нужны Docker с compose, домен и [Cloudflare Worker](QUICKSTART-cloudflare-worker.md)
(код в `cloudflare/worker.js`).

```bash
git clone https://github.com/scp-oss/tproxy-web && cd tproxy-web
cp .env.example .env        # впишите HOSTNAME_ARG и CF_WORKER
docker compose up -d --build
docker compose logs | head  # адрес панели, логин и пароль
```

Контейнер работает в сети хоста (`network_mode: host`): модули открывают
свои порты сами, когда их включают в панели.

### Что настроить снаружи

- **WEB-прокси** требует порт 443 на стороне клиента. Направьте
  `https://<домен>/<base_path>` на HTTP-вход (по умолчанию `127.0.0.1:19443`) из своего
  nginx/NPM/Caddy, либо откройте прямой HTTPS-вход и положите сертификат в
  `./certs/fullchain.pem` и `./certs/privkey.pem`. Оба адреса меняются в панели
  (карточка WEB → «Порты входа») сразу, без пересоздания контейнера;
  `FRONT_ADDR` / `FRONT_TLS_ADDR` в `.env` — только начальные значения.
- **MTProto** — проброс выбранного в панели порта TCP.
- **SOCKS5** — для локальной сети, наружу не открывайте: протокол без
  шифрования, провайдеры его распознают.

## Звонки

Cloudflare Worker пропускает только TCP, а голос звонков Telegram идёт по
UDP. Поэтому для звонков нужен **выход за границу**: Shadowsocks-сервер
(например, inbound Shadowsocks-2022 tcp+udp в 3x-ui). Ссылку `ss://…`
вставьте в панели в блоке SOCKS5.

- **iPhone**: прокси SOCKS5 из панели + «Использовать для звонков».
- **Android**: Telegram 13.x не пускает звонки через прокси вообще
  (в коде звонков прокси передаётся как `null`). Для звонков — модуль
  **WireGuard для Telegram**: в панели «Добавить устройство», на телефоне
  приложение WireGuard (APK лежит прямо в панели, на случай если сайт или
  магазин недоступны) и QR-код профиля. В туннель идут только сети
  Telegram, остальной интернет телефона — как обычно. Туннель идёт от
  телефона до сервера в своей сети, провайдер его не видит.

### Звонки дома через роутер Keenetic

Роутер заворачивает трафик Telegram всех устройств в туннель WireGuard до
панели, панель — во внешний узел. Телефоны не настраиваются, Android тоже
звонит. Всё делается в веб-интерфейсе Keenetic, без консоли; пошагово — в
панели, вкладка «Звонки», блок «Звонки дома через роутер Keenetic». Коротко:

1. Панель → WireGuard → устройство «Keenetic» → скачать `.conf`.
2. Keenetic: *Управление → Общие настройки → Изменить набор компонентов* →
   «WireGuard VPN».
3. *Интернет → Другие подключения → WireGuard → Загрузить из файла*; снять
   «Использовать для выхода в интернет», включить.
4. *Сетевые правила → Маршрутизация → Добавить маршрут* («Маршрут до сети»,
   интерфейс — это подключение) для каждой сети Telegram:

## Обновление и откат

```bash
git pull && docker compose up -d --build
```

Тот же том `/config` — секреты и ссылки клиентов не меняются.

## Переход со старой версии (7 контейнеров)

Новая версия читает тот же том настроек (`config_data`), ссылки клиентов
остаются прежними:

```bash
# в папке старой установки
docker compose down
docker rm -f tproxy-web-mtproto-1 tproxy-web-socks5-1 2>/dev/null
# в папке новой: в .env укажите CONFIG_VOLUME=<имя старого тома>, например tproxy-web_config_data
docker compose up -d --build
```

Старые файлы (compose-варианты, init.sh, cover, panel-admin и т.д.)
лежат в `legacy/` для справки.
